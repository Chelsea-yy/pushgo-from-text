# 安全、隐私与依赖边界

## 默认行为

- 默认离线提取与整理，不访问模型、原文链接或外部 OCR，不自动上传和发布。
- 模型调用需要显式 `--provider openai` 和本机配置。材料会发送到配置的 API，可能计费；请先确认接口可信且材料可上传。
- 密钥不写入草稿、日志或公共文档；接口错误不转储返回正文，不跟随重定向，不自动重试。
- 原始文件只读。输出目录必须不存在，不接受覆盖开关，不允许位于本工作目录的 `raw_data` 中。
- `article.json` 和 `review.md` 包含完整提取原文；其他导出也可能含私人信息。所有产物应放在被忽略的 `.local` 中。自定义目录没有自动 Git 隐私保护，提交前必须检查。
- 文档中的宏、提示词、链接不执行。模型仍可能误解材料或受提示词注入影响；自动字面校验不是完整防护，不可无人审阅后发布。
- HTML 转义文本及属性，图片/链接限制协议和路径，预览复制时重新清理当前 DOM。预览页面只允许固定脚本，不接受材料作为代码。
- 生成时不请求图片。手动加入的 HTTP(S) 图片在浏览器预览中仍可能产生网络请求和来源暴露；敏感内容请使用本地素材并在平台自行上传。模型不能自行提供图片块。

## 输入限制与解析风险

输入限制为普通文件、20 MB、150000 提取字符，PDF 上限 100 页。DOCX 是压缩格式，大小检查不能完全阻止恶意压缩包的内存消耗；字符限制也不是操作系统级资源隔离。当前版本用于自己信任的材料，不应直接作为公网匿名文件解析服务。未来网页版本必须增加独立进程/容器、解压预算、超时和上传隔离。

PDF/DOCX 只提取可读文字，不保证多列表格、图片、文本框、修订、页眉页脚及二维码全部可见。PDF 页码与 Word 提取后段落位置含义不同，后者不是 Word 的排版页码。扫描件需要先进行本地 OCR，再人工检查。

## 当前依赖通告

本次 `npm audit` 报告 3 项中等级记录，来自同一条传递链：

`mammoth 1.13.0 → argparse 1.x → sprintf-js 1.1.3`

通告：[GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)，特制精度格式串可造成拒绝服务。检查时 npm registry 最新 `sprintf-js` 仍为 1.1.3，属于受影响范围。`npm audit fix --force` 建议把 Mammoth 降到非常旧的版本，不能视为合理修复，因此未执行。

本工具调用 `mammoth.extractRawText` 的库 API，未调用 Mammoth CLI 的 `argparse/sprintf-js` 参数格式化路径。已核查 Mammoth 入口与 CLI 的引用位置，风险在当前调用方式下有限，但不等于已经修复，也不保证未来依赖版本行为。

- CI 使用 `npm audit --omit=dev --audit-level=high`，高危或严重通告会失败，中等级仍公开记录。
- 下一步跟踪上游修复，或评估有解压和 XML 资源预算的 DOCX 提取替代方案。
- 不宣称依赖审计零问题；未来公开上传服务上线前必须重新评估。

## 平台与发布

秀米账号、登录、上传、草稿保存和最终发布由用户授权控制。HTML/Word 可编辑结构不能证明秀米接受；平台兼容性必须用虚构材料导入、修改、保存、重开来验证。没有证据就保留“未验证”。

代码经检查后可以同步功能分支和 PR。合并主分支、选择许可证、创建发布、部署、付费操作或公开原始材料仍需要维护者明确确认。
