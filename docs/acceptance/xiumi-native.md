## 1. 验收目标

外部工具生成的一份校园活动预告／招新内容，经官方明确支持且获准使用的路径进入真实秀米稿件，形成可独立操作的原生组件；在秀米内修改、保存、退出并重开后仍保持原生结构和可编辑性。

“原生组件”在本次验收中指由秀米正常编辑界面识别、可按模块选择和操作的结构，且符合官方对该导入能力的书面定义。只看到文字光标、预览一致、HTML 可用或接口返回成功，都不能单独证明原生结构成立。

## 2. 前置条件：先官方支持，再最小平台验证

所有前置条件满足后，才可以开始第 4 节：

1. 取得可追溯的官方说明，明确支持外部生成内容写入秀米原生组件，并给出正式路径、输入约定及组件范围；只有“同步”“打开编辑器”或一般合作答复不足。
2. 单独确认该写入能力的账号／应用授权、申请要求、配额、费用和使用限制。个人可申请同步应用、开源分发许可均不能替代原生写入授权。
3. 若方案涉及开源分发，明确相关 SDK／示例再分发、商用／非商用及模板素材许可；未确认的分发行为保持阻塞。
4. 主控完成研究复核，用户另行明确批准真实测试范围、所需登录／申请及任何费用。批准本次文档研究不等于批准上述外部操作。
5. 由用户或其明确授权的测试者在允许的测试环境、测试账号和独立测试稿件操作，使用完全虚构文本与自行生成或明确获准的占位图片。证据先脱敏再提供。

若官方表示不支持，记录“不支持，验收目标无法按当前要求完成”；若官方未明确答复，保持“阻塞，未实测”。不得尝试私有接口、逆向原生数据、浏览器注入或自动化绕过，也不得以 HTML 粘贴兜底。

## 5. 证据记录格式

实际测试前不创建虚假截图、响应或成功日志。未来证据的位置与保存方式须另行获准；本次只修改这两份文档，不生成其他证据文件。

每次测试使用一条主记录，字段如下：

| 字段 | 填写要求 |
| --- | --- |
| 测试编号／样例版本 | 非账号标识的测试编号，关联 T0—T6。 |
| 时间及环境 | 日期、时间、时区；浏览器版本；秀米可见版本（若无则写“页面未显示”）。 |

| 授权范围 | 是否允许登录、申请、写入及可能费用，只记录授权结论和范围，不记录私人身份信息。 |
| 输入与组件映射 | 外部生成内容摘要、正式输入格式与版本、每个外部模块对应的秀米组件类型。 |
| 操作与预期 | 步骤编号、正常用户操作、预期结果。 |

## 6. 通过标准与反例

以下条件全部满足且经主控复核后，才记为“最小真实验收通过”：

- 有可追溯的官方书面依据，明确支持本次外部内容到秀米原生组件的路径；测试处于实际授权和许可范围。
- 第 3 节外部生成的样例通过该路径实际进入秀米，而非只创建空白稿件、打开页面或在秀米手工重建。
- 全部样例模块及所要求的卡片子结构可按官方对应的原生类型独立选择；文字／样式、顺序、复制删除、图片、链接操作均完成且不破坏其他模块。
- 保存后离开并重开，以上内容、层级和修改均保留，文字及图片仍能原生操作。
- T0—T6 的实际证据完整、脱敏且可关联；所有能力缺口已明确；主控复核结论为通过。

以下结果均不能通过：

- 本地渲染或预览成功，但没有真实秀米写入记录。
- 秀米向外同步 HTML／图片成功，或 UEditor 插件回传内容成功。
- 打开 `/auth/partner/edit`、新建空白稿件、获得稿件编号或接口返回成功，但没有原生结构及保存重开证据。
- HTML 粘贴、整篇图片、外部页面嵌入，或仅能编辑一个整体富文本而无法按要求操作原生模块。
- 依靠人工逐块重建、私有协议、逆向、内部数据修改或自动化绕过实现。
- 仅有开源再分发许可、个人同步应用资格或一般接入许可。
