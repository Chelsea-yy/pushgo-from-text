# 活动推送模块与选材

本页是写作方法，不是必须全部出现的模板，也不是已证明的传播规律。依据是小规模校园活动参考文章的可读文本和策划案比较；指标可见性与正文质量分开。

## 1. 模块各自回答什么

| 模块 | 读者的问题 | 应写的内容 | 取材与删减 | 常见失败 |
| --- | --- | --- | --- | --- |
| 标题 | 这是什么，是否与我有关？ | 活动/议题、对象或一个具体问题；报名/预告属性按实际需要 | 保留辨识度，不塞完整单位链和所有议程 | “重磅来袭”替代信息；无依据倒计时/首届/保证收获 |
| 导语 | 为什么现在值得继续读？ | 一个与活动直接相关的问题、情境或简短背景，接到本次活动 | 背景通常压到1–3短段；不原样搬整页政策 | 大背景一直讲到读者还不知道活动是什么 |
| 活动定位 | 这场活动究竟要讨论什么？ | 主题、形式、面向谁、与普通讲座的内容差别 | 从目的和核心环节提炼1–2句 | 只有愿景口号；虚构独家性 |
| 读者价值 | 我为什么参加？ | 对特定人群可了解/讨论的问题，对应实际内容 | 从目的、议题、环节或嘉宾经验转译，不添加结果承诺 | “拓展视野、碰撞思想”无具体对象；把交流平台写成融资保证 |
| 基本信息 | 我能不能去、要预留多久？ | 日期、时段、地点或真实通知机制、对象/条件、必要的主办信息 | 用紧凑短行；区分活动时间与报名截止、总时段与子议程 | 错把截止当日期；擅自公开内部地址；写不存在的通知制 |
| 内容亮点 | 值得把时间用在哪些内容上？ | 每项一个清楚主题+一句具体解释/与读者的关系 | 通常选3–5个互不重复的内容点，材料少可更少 | 机械凑五大亮点；把同一卖点说三次 |
| 嘉宾/企业/项目 | 为什么这些内容可信或有独特视角？ | 姓名/机构或类别、相关身份、与议题有关的经验/内容 | 长履历保留最相关1–2层身份；名单不确定时可只说拟邀领域 | 用头衔堆字数；拟邀变确认；复制参考里新增的履历 |
| 议程/体验流程 | 现场怎么安排，我能参与什么？ | 公开环节与必要时段，明确分享/问答/交流区别 | 简单活动可以一句流程；复杂论坛按层级而非逐条人名 | 把主持词、物料、会务分工和会后复盘全搬进来 |
| 报名行动 | 我现在怎么做，之后会怎样？ | 一个主要动作、真实入口、截止、资格/审核/通知及费用（仅已知项） | 收束只保留一个主要行动，可与前置信息形成轻量提醒 | 无二维码仍写“扫下方”；臆造免费/先到先得/剩余名额 |
| 结尾 | 我应记住什么？ | 贴合主题的一两句邀请；必要时重复日期/行动，不再讲一轮背景 | 可没有单独“结语”标题 | 再次堆整段宏大愿景；“不见不散”掩盖报名缺口 |
| 组织/署名 | 谁负责，是否有必要注明？ | 已确认的组织角色和必要署名 | 多单位可放末尾；赞助/协办/主办严格区分 | 把支持单位升级主办；把审稿空栏当正式署名 |

“基本信息”“报名行动”是读者任务，不一定是独立章节。有真实入口时可前置再轻量收束；资产缺失时在审核中阻塞，不造一个假入口来满足结构。

## 2. 选择顺序，不照抄顺序

### A. 问题—收益型

适合求职分享、技能交流、职业或创业决策场景。

标题 → 一个具体问题 → 活动定位 → 基本信息/可用报名入口 → 可讨论的收获 → 嘉宾/企业证据 → 必要流程 → 最后提醒。

重点是让“企业/嘉宾很强”服务于“读者能接触什么内容”，不要把企业宣传册当推送主体。缺少企业已核实的最新营收/融资等数字时，删掉数字通常比继续扩写更稳妥。

### B. 议题—理解型

适合前沿科技、学术论坛和跨学科议题。

标题 → 一两句问题背景 → 本次活动 → 基本信息 → 议题亮点 → 嘉宾/形式 → 行动。

讲清术语和问题的关系，不需添加未经提供的技术现状、治疗成果、市场规模或专家观点。技术愿景与已经实现的能力分开。

### C. 资源—交流型

适合项目分享、产学研交流、产业/资本对话。

标题 → 读者需要理解的资源或问题 → 谁与谁交流 → 基本信息 → 具体议题/项目领域 → 公开议程 → 行动。

可以说计划搭建交流机会，不能说到场必然获得投资、合作、岗位或资源匹配。项目名单有冲突时，宁可写原材料支持的领域，不拼出一个最终名单。

### D. 机会—招募型

任务/角色 → 具体参与内容 → 条件/时间投入 → 已确认支持 → 申请步骤/截止 → 联系渠道。

招募中的“可获得证明/学分/补助/优先资格”必须有来源。附带招募不要抢走主活动的主要报名动作；必要时拆为单独推送。

## 3. 从策划语言到读者语言

以下全部为独立虚构的编辑例子，不是参考文章原句。

| 策划材料 | 不合适的改写 | 可接受的写法与边界 |
| --- | --- | --- |
| 目的：促进校园技术项目交流；环节：案例分享、提问 | 参加即可解决项目难题，获得行业资源 | “听几种项目尝试，带着你的问题参与讨论。”支持的是分享/提问机会，不是问题必然被解决 |
| 拟邀请两类从业者，名单未定 | 两位行业领军人物确认到场 | “计划邀请相关从业者交流。”或暂不写嘉宾段，待确认名单 |
| 形式：演讲+问答；无具体时段 | 14:00主旨，14:30问答 | “活动拟设置分享与问答环节。”不编精确时间 |
| 内部观众规模80人 | 仅剩80席，先到先得 | 计划规模不代表对外名额、余量或录取机制；可以完全不写 |
| 报名方式：扫码；二维码未提供 | 扫描下方二维码立即报名 | 洁稿暂不写扫码句；审核记录说明需要真实二维码/链接并阻塞发布 |
| 具体地址在内部执行页 | 把完整地址写在标题下 | 先确认是否公开。未确认时不自创“报名后通知”，将地点留在审稿问题清单 |
| 目的：搭建长期交流平台 | 加入即可获得长期一对一指导 | “围绕相关问题展开交流。”不能增加后续服务承诺 |

## 4. 长短与节奏

- 先决定信息任务再分配篇幅。复杂论坛的嘉宾和议程可能较长；不要为了“像优质推送”把简单分享会也写成论坛长文。
- 第一屏尽快出现读者问题、活动身份或最必要信息，避免连续多段宏观背景。
- 标题、导语、收益和亮点允许呼应，但不能只是同一列表重写。
- 段落通常一项任务，长履历拆成身份与关联经验；列表用于平行内容，不用来掩盖逻辑重复。
- “嘉宾介绍”和“议程”若重复列同一批人，优先合并或只在一处具名。
- 不使用“众所周知/无疑/必将/一次解决所有问题”等无依据断言。明确具体，胜过堆“高端/重磅/顶尖”。

## 5. 参考学习的证据边界

应保留样本编号、可读模块与次序、每模块的功能、正文获取方法、指标是否有证据和未知原因。图中信息不能只凭空标题补写；对回顾只学习事件叙述方法，实际结果不能反向补入预告。

阅读数不是转发数，点赞不是在看，在看不是分享。后台“分享人数”和“分享次数”也不同；“10万+”是区间下界而非精确100000。不同发布时间、账号体量和分发方式会影响表现，小样本不能证明某个模块带来高转发。没有指标时依然能分析编辑结构，但应称为优质参考学习而非高传播规律训练。
